# Account recovery generator

The account recovery (lost second factor) is a large part of the IAM configuration: a points-based
flow with several confirmation rounds (IAM flows can't loop, so the rounds are unrolled), Lua scripts
that call the Adminapp REST API and send emails, and related self-services. It is generated by
`generate.py` instead of being edited by hand.

```
tools/iam-recovery/generate.py iam/iam-config.yaml
check_config.py iam/iam-config.yaml          # from the airlock-iam-config skill, or validate otherwise
```

- `generate.py` - flow structure, methods (`METHODS`: key, option name, points), `ROUNDS`, `THRESHOLD`,
  generated self-services; `strip()` removes a previous run first, so it can be run again at any time.
- `lua_lib.py` - Lua helpers inserted into the scripts: Adminapp REST calls (technical administrator
  `selfreg-lookup`), contact lookup (email and mobile number of up to 5 contacts as outputs
  `contact1..5` / `phone1..5`), random codes.
- `smsdefs.py` - mTAN/SMS parts: method "SMS code to the mobile number" (context data `mtan_number`),
  SMS switch `smsEnabled` (false in the template), SMS settings `recoverySmsSettings` (dummy gateway),
  self-service "Mobile number". An SMS snippet (e.g. `vmware/iam/snippets/sms-truesenses.yaml`) connects a
  real gateway, sets the switch and adds SMS event subscribers for the contacts (step IDs
  `recovery-code-send-<n>`, `recovery-confirm-request-<n>`).
- `waitdefs.py` - waiting period: method `RECOVERY_WAIT` (10 points, offered with more points than the known
  browser gives), saved state (context data `recovery_state`, `recovery_wait_until`), restore script after the
  known browser (continue in the next round after the wait, or in the same round while waiting), "come back
  later" option, deletion of the state (success, not possible, normal login = cancel).
- `iddefs.py` - ID document: method `RECOVERY_ID_DOCUMENT` (25 points, only with a stored document; the QR code
  page names the stored type - one page variant per type, the "back to the QR code" goto targets a marker step in
  front of them -, per round own copies of the PXL Vision steps of the self-registration, comparison of type and
  number), self-service "Verify identity" (`identity-verification`: PXL check, stores `idp_doc_number` /
  `idp_doc_type`, first/last name filled in or - if different - updated on request; country = issuing country of the document; no birthdate) with step-up application
  `identity-step-up` (second factor of this session, tag `STRONG_AUTHENTICATION`).
- `yamlsteps.py` - small helpers to find and replace plugins in the YAML text.

Not generated (maintained by hand): texts (`designkit/src/assets/custom/i18n/*.properties`,
`iam/loginapp-texts/`, `iam/adminapp-texts/`), database columns (`applications/packages/iam/iam/scripts/init_db`:
`email_alt`, `recovery_*` incl. `recovery_state`, `recovery_wait_until`; `mtan_number` is a standard column).

Workflow: run on `base/iam/iam-config.yaml`, review the diff, copy the result into the instances
(their `iam/iam-config.yaml` follows the template; instance add-ons are snippets).
